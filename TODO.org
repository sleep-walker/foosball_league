*** [ ] Broadcast zprávy organizátora hráčům
    Open questions (decide before implementation):
    - Recipients: all spectators on Live View, or only registered
      players?  Probably both — Live View shows a banner, registered
      players see a toast in their app.
    - Persistence: ephemeral (websocket only) or stored?  If stored,
      need =broadcasts= table with FK to tournament + author + text +
      created_at, plus retention policy.  Ephemeral is simpler v1.
    - Authorisation: tournament owner + co-organisers (=tournament_organizers=
      M2M already exists, see Tournament.co_organizers).
    - Rate limiting: at least basic anti-spam (e.g. 1 broadcast per
      10 s per organizer).

    Proposed v1 (ephemeral, all-recipients):
    - =POST /api/v1/tournaments/{id}/broadcast= body ={"text": "..."}=,
      auth = owner/co-organizer.
    - Server publishes =Event("broadcast", tournament_id, {text, from})=
      via =event_hub=.
    - Live View renders a 5 s top-of-screen banner.
    - Tournament-detail page renders a toast.
    - No DB persistence in v1.

** Perf debt 🐌
*** [ ] Eager-loading audit (=lazy="selectin"=)
    31 relationships across the models use =lazy="selectin"= as default,
    which forces an extra SELECT for the relation on every access — even
    for endpoints that don't touch it (e.g. =GET /leagues= loads each
    league's tournaments, seasons, rule_presets, members; each tournament
    then expands its stages, matches, teams, registrations, applicants,
    co-organizers → exponential fan-out).

    Plan:
    1. Add SQL counting fixture (=event.listens_for(Engine, "before_cursor_execute")=
       in conftest) and assert sane query counts on key endpoints
       (=GET /leagues=, =GET /tournaments=, =GET /tournaments/{id}=).
    2. Switch problematic relations to =lazy="raise"= (or unset).
    3. Add =selectinload(...)= to the few CRUD/repository queries that
       actually need the relation.
    4. Repeat per-domain — Players is already lean, start with Leagues.

    Currently safe: =get_tournament= in tournaments/crud.py already does
    explicit =subqueryload= chains, so the selectin defaults are
    redundant duplicate work there.
